Policy gradient → PPO → GRPO

Before you start: in your GRPO run, one response for a prompt was good (A > 0) and is already 50% more likely under the current weights than when vLLM sampled it. Should the optimizer keep pushing it up? Commit to yes or no. The answer is in section 2.

1REINFORCE: push up whatever you sampled

    $$\grad J=\E\big[\grad\log\pit(\Y\mid\X)\cdot\Adv\big],\qquad \Adv=\Rw-\bb$$

    The baseline b adds no bias, since \(\E[\grad\log\pit]=\grad\sum\pit=\grad 1=0\), but it cuts the noise a lot. What it can't fix: nothing limits how far one step moves the policy.

    All rewards in the toy are ≥ 0. Without a baseline, what happens every time a mediocre response is sampled?
    It gets pushed up (R > 0), just less than a good one. Which responses win then depends heavily on which ones happened to be sampled: high variance. With a baseline, A = R − b is negative for below-average responses, so they get pushed down.

    2The ratio ρ and PPO's clip

      $$\rr=\frac{\pit(\Y\mid\X)}{\piold(\Y\mid\X)}\qquad L^{\text{CLIP}}=\E\Big[\min\big(\rr\Adv,\ \operatorname{clip}(\rr,1-\eps,1+\eps)\,\Adv\big)\Big]$$

      Worked example (this answers the opening question)

      ε = 0.2, A = +1, ρ = 1.5: min(1.5·1, clip(1.5, 0.8, 1.2)·1) = min(1.5, 1.2) = 1.2. That value is a constant, so the gradient is 0. No, stop pushing.
      Flip the sign, A = −1: min(−1.5, −1.2) = −1.5, which still depends on ρ, so the gradient is active and pushes ρ back down. A mistake can always be undone.
      Try it: the clipped objective for one response
      Hover the plot to move ρ.
      ε = 0.2, A = −1, ρ = 0.7. Does this sample contribute a gradient?
      No. A bad response that is already 30% less likely (ρ < 1 − ε) sits on the flat part: min(−0.7, −0.8) = −0.8, a constant. PPO stops pushing it down.

      3Why it matters: K epochs on one batch

        Try it: same batch, naive vs PPO
        Naive: maximize ρ·A
        PPO: min(ρA, clip(ρ)A)
        Pink tick = πold. PPO's ρ can drift a little past 1 ± ε: one step can overshoot, and pushing the bad responses down indirectly lifts the good one. But it stays bounded.
        Why does reusing a batch blow up the naive objective but not PPO's?
        Naive ρ·A grows without limit, so on stale data the optimizer keeps pushing the same responses step after step. PPO's objective goes flat once ρ leaves [1−ε, 1+ε] in the helpful direction, so those samples stop contributing a gradient.

        4GRPO: PPO without a critic

          $$\Adv_i=\frac{\Rw_i-\gmu}{\gsig}\quad\text{(same }\Adv_i\text{ for every token of response }i\text{), then the PPO clip from section 2}$$
          • What's dropped: RLHF-style PPO trains a value model (critic) to predict expected reward. GRPO uses the mean of G = 8 samples instead (your run: 32 prompts × 8).
          • β = 0 (as in DAPO): no KL term, so no reference model to load.
          • scale_rewards: "group" (default) divides by each group's σ, "batch" by the σ of the whole batch. The mean is always the group's own.
          • importance_sampling_ratio: vLLM and the trainer compute slightly different token probabilities. TRL reweights by πtrainer/πvLLM, capped. It's another ρ, for a different mismatch.
          All 8 completions of a prompt score 1. What does GRPO learn from that prompt?
          Nothing. σ = 0, so every Ai = 0 (TRL adds a tiny ε to σ, so you get exact zeros). The compute is wasted. Fixes: harder prompts, or filter out such groups (DAPO's dynamic sampling).
          Summary
          1. REINFORCE pushes up the log-prob of sampled responses in proportion to the advantage A = R − b. It's unbiased, but noisy and its step size is unbounded.
          2. PPO reuses a batch for K epochs via ρ = πθ/πold, and clips so the gradient vanishes once ρ leaves [1−ε, 1+ε] in the helpful direction.
          3. GRPO = PPO-clip with the critic replaced by group-normalized rewards. Equal rewards in a group give no signal, and β = 0 means no reference model.
